## What went well
1. Plan review paid off: 3 high + 4 medium defects fixed before any code (read authorization, credential isolation, rate limits before public deploy) — zero escaped defects at ship.
2. Executable specs + speclock + fake Mattermost let each slice go red -> green fast (s2 implement-to-CP-S ~0.6 h); live CP-S checks confirmed behaviour on the real server every slice.
3. Fast front half: discover -> CP-C in ~2.3 h with all ADRs carrying scored-able predictions; 4 of 4 due predictions right.

## What hurt
1. Runner environment failures (permission mode, SIGHUP) cost two implement runs and an extra handoff each.
2. Environment facts rediscovered repeatedly: port 8080 vs 8000 (s2 verify note), Python 3.12 vs 3.14 (TODOS), MCP client tool-list caching, PowerShell/WSL quoting.
3. Test harness gaps found late: `pytest tests` silently skipping unit tests from s1 until s3; wall-clock flake in rate-limit tests.

## Root causes
- Runtime/operational facts live in handoffs and verify notes, not in a stable AGENTS.md section, so each new agent session rediscovers them.
- The runner's permission mode was a local, uncommitted runners.toml edit with no preflight check that the gate commands can execute.
- DoD has no rule that the default test command runs every suite and that time-based tests use an injected clock, so the conftest scoping bug passed s1 verify (it was filed as a TODO instead of blocking).
- Process friction went to handoffs, not process-feedback.md, so the log was empty at retro time.

## Kit lessons proposed (Rob approves; format in .eng/templates/kit-lesson.md)
- L1: When a headless implementer run starts, preflight that it can execute the gate commands (eng-check, test runner) before taking the slice, because a permission-mode refusal otherwise burns a whole run and a handoff. (origin: mmbridge v0.2.0 retro; confirmations: 1; status: hypothesis)
- L2: When a project ships trunk-based (main + tag), let eng-ship accept CP-P on the tagged commit instead of PR/CP-D, because the PR-shaped text makes the agent improvise the release path. (origin: mmbridge v0.2.0 retro; confirmations: 1; status: hypothesis)
- L3: When code has time- or rate-based behaviour, inject the clock in tests from slice 1, because wall-clock tests flake intermittently and are found late. (origin: mmbridge v0.2.0 retro; confirmations: 1; status: hypothesis)
- L4: When an MCP server's tool surface changes, restart the client's MCP connections before manual verification, because clients cache tool lists and report stale tools as a product bug. (origin: mmbridge v0.2.0 retro; confirmations: 1; status: hypothesis)
- L5: When the planner edits repo files on a Windows host through WSL, ship multi-line content as a base64 pipe into a single-quoted bash -lc, because nested PowerShell/bash quoting silently mangles text. (origin: mmbridge v0.2.0 retro; confirmations: 1; status: hypothesis)
- L6: When friction appears mid-cycle, append it to process-feedback.md in the same session, because handoffs are not read by the retro pass and the log ends up empty. (origin: mmbridge v0.2.0 retro; confirmations: 1; status: hypothesis)
