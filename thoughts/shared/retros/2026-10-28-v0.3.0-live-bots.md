## What went well
1. The front half was fast and sound again: discover to CP-C in about 2.3 h with 5 ADRs carrying scorable predictions. Two plan-review rounds on each plan caught about 10 high findings before any code.
2. Slice reviews on the stateful slices caught about 14 real bugs (rotation identity, delivery-id binding, commit-ordered seq/alive, catch-up paging, team-less D-channel discovery) before ship.
3. The mid-plan delta (drop the allow-list) went through the proper path: delta plan, 2 plan reviews, CP-A amendment, CP-C re-lock. It became one small slice (lb4b) with no rework.
4. `push_permission: standing` removed the push round trips (prediction right). Docs-only pushes (L-004) kept state on origin.

## What hurt
1. Several CP-S demos asked Rob for live steps that could not run until lb5 wired the listener, so live checks were deferred 5 times. The final real-MM restart check is still open.
2. Review-loop overhead: 6 Codex rounds each on lb4 and lb5, made worse by the eng-run parser printing "No findings." over real findings, and by codex missing from PATH.
3. There is a communication mismatch on the wake rule. D1 ("every post... No mention required") was in the delta plan Rob approved at CP-C, but at ship Rob said he was surprised that no @mention is required. He then approved CP-P ("No need to fix @mention behavior"). The behaviour reversed the original TODO title ("@mention-only responding") and was stated only as a rule in plan prose, never as a concrete demo at CP-S.
4. 3 flaky timing-race unit tests under the full suite shipped as a P2 TODO.
5. Concurrent agents briefly raced on PROJECT_STATE/TODOS during ship and needed a manual restore.

## Root causes
- Slices were cut by component (store, ledger, listener, dispatcher), not end-to-end, so no live path existed until the last slice. CP-S had nothing live to show.
- Approval asks state behaviour changes as rules, not as a before/after example, so a reversal of a long-standing expectation (mention-only) was not noticed until the live demo.
- The DoD time rule covers wall-clock time but not concurrency or timing races (sleep-based waits on threads/tasks).
- There is no single-writer convention for shared state files when more than one agent runs on the project.
- Kit runner defects (parser, PATH, sandbox loopback) push manual work onto every review round.

## Kit lessons proposed (Rob approves each; for Yana / eng-process kit; no project details)
- K-1: When a change reverses a user-visible default the owner has relied on, put a one-line Before -> After example in the approval ask and demo it at the slice checkpoint, because rule-style prose gets approved without the owner noticing the reversal. (origin: this retro; confirmations: 1; status: hypothesis)
- K-2: When the code-review runner runs tests in a sandbox that cannot bind loopback ports, treat its test results as partial and never as coverage for socket/integration tests, because "No findings" there hides suites that never ran. (origin: this retro; confirmations: 1; status: hypothesis)
- K-3: When two or more agents work one project at once, give one agent ownership of writes to PROJECT_STATE/TODOS (others append via handoff or inbox), because concurrent edits to the shared state files race and overwrite each other. (origin: this retro; confirmations: 1; status: hypothesis)
- K-4: When a plan builds a multi-component live feature, slice it so a thin end-to-end live path exists early (walking skeleton), because component slices leave every checkpoint with nothing live to approve. (origin: this retro; confirmations: 1; status: hypothesis; related to L-009)
- Kit bugs for Yana (not lessons): eng-run code-review parser drops `[P1]/[P2]` findings (P1); runner PATH lacks the nvm bin for codex; eng-spec trace misreports an amended approved design (P3).
